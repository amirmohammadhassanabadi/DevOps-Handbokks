# 104.1 — Storage Devices, Partitioning, Filesystems and LVM

## Storage Devices

A **storage device** is hardware used to store data persistently.

- ### HDD — Hard Disk Drive

     An HDD is a mechanical storage device that stores data on **magnetic spinning platters**. A read/write head moves across the platters to access data.

- ### SSD — Solid-State Drive

  An SSD stores data in **flash memory** and has no moving mechanical parts. SSDs generally provide lower latency and higher I/O performance than HDDs.

HDD and SSD are **different storage technologies**, not simply different generations of the same device.

---

## Storage Interfaces and Protocols

Storage devices communicate with the system through storage interfaces and protocols.

**Common examples:**

| Interface / Protocol | Description                                             |
| -------------------- | ------------------------------------------------------- |
| **MFM**              | Historical interface used by very early PC hard drives  |
| **IDE / ATA / PATA** | Older parallel storage interface                        |
| **SATA**             | Serial interface widely used for consumer HDDs and SSDs |
| **SCSI**             | Older enterprise/workstation storage interface          |
| **SAS**              | Serial Attached SCSI; enterprise storage interface      |
| **NVMe**             | Storage protocol designed for SSDs, normally using PCIe |

**Important:** The physical drive, interface, controller, and protocol must be compatible.

For example:

* An IDE/PATA drive cannot simply be connected to a SATA controller.
* A SAS drive requires a SAS-capable controller.
* SATA drives can generally be used with SAS controllers, but SAS drives cannot be used with ordinary SATA controllers.

### NVMe

**NVMe (Non-Volatile Memory Express)** is a storage protocol designed specifically for non-volatile memory such as SSDs.

Unlike SATA/AHCI, NVMe normally communicates through **PCIe**, allowing much higher parallelism and lower latency.

---

## Storage Form Factors

A **form factor** describes the physical shape, size, and connector arrangement of a device.

Common SSD form factors include:

* **2.5-inch SATA SSD**
* **M.2 SSD**
* **PCIe add-in-card SSD**

**M.2 is a form factor, not a protocol.**

An M.2 drive can use different interfaces, such as:

* SATA
* PCIe/NVMe

Therefore:

> M.2 ≠ NVMe

A common modern combination is an **M.2 NVMe SSD**.

### mSATA

**mSATA** is an older small-form-factor SATA SSD standard. It has largely been replaced by M.2.

---

## Hot-Plug / Hot-Swap

A **hot-pluggable device** can be connected or disconnected while the system is running.

In servers, hot-swappable drives are commonly installed through a **hot-swap backplane**.

Hot-plug support depends on the complete hardware/software configuration, not only on the storage protocol.

Enterprise servers commonly use hot-swappable:

* SAS HDDs
* SAS SSDs
* SATA HDDs/SSDs in supported backplanes

# Linux Block Devices

Linux represents hardware devices through **device files**, usually located under:

```text
/dev
```

A **block device** is a device that provides storage in addressable blocks and supports random access.

Examples:

```text
/dev/sda
/dev/sdb
/dev/nvme0n1
```

Partitions are also represented as block devices:

```text
/dev/sda1
/dev/sda2
/dev/nvme0n1p1
```

### Block Device vs Character Device

| Feature            | Block Device                     | Character Device                  |
| ------------------ | -------------------------------- | --------------------------------- |
| Access             | Typically supports random access | Stream-oriented access            |
| Data handling      | Data is accessed through blocks  | Data is accessed as a stream      |
| Examples           | HDD, SSD, USB storage            | Keyboard, serial device, terminal |
| Examples in `/dev` | `/dev/sda`, `/dev/nvme0n1`       | `/dev/tty*`, `/dev/zero`          |

The distinction is primarily about **how the kernel interface operates**, not simply whether a device is physically sequential or random.

For example, magnetic tape devices are normally character devices:

```text
/dev/st0
/dev/nst0
```

Tape is sequential media, but the important Linux concept is that its driver exposes a **character-device interface**.

### Block Device I/O

Block devices commonly participate in:

* Random access
* Buffered I/O through the Linux page cache
* Filesystem storage
* Partitioning
* LVM
* RAID

A filesystem such as `ext4` or `XFS` can be built on top of a block device.

# Useful Commands for Block Devices

- ### `lsblk`

  `lsblk` lists block devices in a tree-like structure.
  
  ```bash
  lsblk
  ```
  
  Example:
  
  ```text
  NAME        SIZE TYPE MOUNTPOINTS
  sda         100G disk
  ├─sda1       50G part /
  └─sda2       50G part /home
  sdb         500G disk
  └─sdb1      500G part /data
  ```
  
  Typical naming:
  
  ```text
  /dev/sda       → whole disk
  /dev/sda1      → partition 1 on sda
  /dev/sda2      → partition 2 on sda
  
  /dev/nvme0n1   → whole NVMe disk
  /dev/nvme0n1p1 → partition 1
  /dev/nvme0n1p2 → partition 2
  ```
  
  Notice the difference:
  
  ```text
  SATA/SCSI:
  sda
  sda1
  
  NVMe:
  nvme0n1
  nvme0n1p1
  ```
  
  `lsblk` can also display filesystem information:
  
  ```bash
  lsblk -f
  ```
  
  `lsblk` obtains device information through interfaces such as sysfs and udev.

- ### `/proc/partitions`

  ```bash
  cat /proc/partitions
  ```
  
  Displays block devices and their partition information recognized by the kernel.

- ### `/dev`

  ```bash
  ls -l /dev/sd*
  ```
  
  Displays device files for devices using names such as `/dev/sda`, `/dev/sdb`, etc.

# Disk, Partition Table and Partition

A disk can be thought of as:

```text
Physical Disk
     │
     ▼
Partition Table
     │
     ├── Partition 1
     ├── Partition 2
     └── Partition 3
```

The **partition table** describes how the disk is divided into partitions.

The two major partition-table schemes are:

* ### MBR
* ### GPT

A partition itself does not automatically contain a filesystem. The normal storage stack is:

```text
Disk
  ↓
Partition Table
  ↓
Partition
  ↓
Filesystem
  ↓
Mount Point
```

With LVM, an additional layer is introduced.

---

- ## MBR — Master Boot Record

  **MBR (Master Boot Record)** is an older partition-table scheme.
  
  Important characteristics:
  
  * Traditional maximum addressable disk size: approximately **2 TiB** with 512-byte sectors
  * Maximum **4 primary partition entries**
  * Supports **extended partitions**
  * Uses a relatively simple partition-table structure
  * Commonly associated with traditional BIOS systems
  
  ### MBR Partition Types
  
  An MBR disk can contain:
  
  * Primary partitions
  * One extended partition
  * Logical partitions inside the extended partition
  
  ### Primary Partition
  
  A primary partition is a normal MBR partition entry.
  
  It can:
  
  * Contain a filesystem
  * Store data
  * Be used for an operating system
  
  An MBR partition table has a maximum of **four primary partition entries**.
  
  ### Extended Partition
  
  An extended partition is a special MBR partition used as a **container for logical partitions**.
  
  Conceptually:
  
  ```text
  MBR Disk
  │
  ├── Primary
  ├── Primary
  ├── Primary
  └── Extended
        ├── Logical
        ├── Logical
        └── Logical
  ```
  
  This allowed MBR systems to overcome the four-primary-partition limitation.
  
  ---
  
- ## 9. GPT — GUID Partition Table

  **GPT (GUID Partition Table)** is the modern partition-table scheme normally used with UEFI systems.
  
  Advantages over MBR include:
  
  * Supports very large disks
  * Supports many partitions
  * Stores a primary GPT header/table and a backup copy
  * Uses CRC32 checksums for integrity checking
  * Uses globally unique identifiers (GUIDs) for partitions
  * Better suited to modern systems
  
  > Linux tools such as **`fdisk`** support both MBR and GPT.
  
  ### Typical GPT Layout
  
  Simplified:
  
  ```text
  Disk
  │
  ├── Protective MBR
  ├── Primary GPT Header
  ├── GPT Partition Entries
  ├── Usable Partitions
  │
  ├── ...
  │
  ├── Backup GPT Partition Entries
  └── Backup GPT Header
  ```
  
### MBR vs GPT

| Feature                             | MBR                          | GPT                                      |
| ----------------------------------- | ---------------------------- | ---------------------------------------- |
| Maximum traditional disk size       | ~2 TiB with 512-byte sectors | Much larger                              |
| Partition entries                   | 4 primary                    | Commonly 128 in standard implementations |
| Extended/logical partitions         | Yes                          | No                                       |
| Backup partition table              | No                           | Yes                                      |
| CRC integrity checking              | No                           | Yes                                      |
| GUID-based partition identification | No                           | Yes                                      |
| Typical firmware association        | BIOS                         | UEFI                                     |

The exact practical limits depend on the implementation and sector size, so values such as "9.4 ZB" should not be treated as a universal usable-disk limit.

---

> ## MBR vs GPT and BIOS vs UEFI
> 
> A common traditional combination is:
> 
> ```text
> BIOS + MBR
> ```
> 
> A common modern combination is:
> 
> ```text
> UEFI + GPT
> ```
> 
> However, these are not absolute rules.
> 
> For example, some UEFI systems can boot from MBR, and some systems provide compatibility modes for legacy BIOS booting.
> 
> The important distinction is:
> 
> **MBR/GPT describe partition-table formats. BIOS/UEFI describe firmware interfaces.**
> 
> They are related, but they are not the same thing.
>

## Sectors

A **sector** is a logical unit of storage addressed by the operating system and storage interface.

Common logical sector sizes include:

```text
512 bytes
4096 bytes
```

Modern disks may use 4K physical sectors while presenting 512-byte logical sectors for compatibility.

Therefore, it is useful to distinguish:

* **Logical sector** → what the system uses for addressing
* **Physical sector** → physical storage organization of the device

SSDs also expose logical block/sector addresses to the operating system while internally managing NAND pages, erase blocks, flash translation layers, and other structures.

---

## Partition Alignment

Modern partitioning tools normally choose aligned partition boundaries based on the device's topology.

A common historical alignment boundary is:

```text
2048 sectors
```

With 512-byte sectors:

```text
2048 × 512 = 1 MiB
```

Proper alignment helps avoid inefficient read/write operations, especially with:

* 4K-sector disks
* SSDs
* RAID devices
* Advanced storage systems

Modern `fdisk` automatically considers device topology and alignment when creating partitions.

**Do not manually force old CHS geometry values for modern disks.**

# Partitioning Tools

- ## `fdisk`

  `fdisk` is a command-line utility for creating and modifying partition tables.
  
  Modern versions support multiple partition-table formats, including:
  
  * MBR
  * GPT
  
  Basic syntax:
  
  ```bash
  sudo fdisk /dev/sda
  ```
  
  The target should normally be the **whole disk**, not an individual partition.
  
  `sudo fdisk /dev/sda` → **Correct**
  
  `sudo fdisk /dev/sda1` → **Incorrect**
  
  `fdisk` is a partition-table tool; it does **not** create the filesystem inside the partition.
  
  ### Common `fdisk` Interactive Commands
  
  | Command | Action                 |
  | ------- | ---------------------- |
  | `m`     | Show help              |
  | `p`     | Print partition table  |
  | `n`     | Create a partition     |
  | `d`     | Delete a partition     |
  | `t`     | Change partition type  |
  | `v`     | Verify partition table |
  | `w`     | Write changes and exit |
  | `q`     | Quit without saving    |
  
  ### Example
  
  ```bash
  sudo fdisk /dev/sdb
  ```
  
  Inside `fdisk`:
  
  ```text
  n
  p
  1
  <Enter>
  +10G
  w
  ```
  
  This creates a partition using approximately 10 GiB.
  
  ### View Existing Partitions
  
  ```bash
  sudo fdisk -l
  ```
  
  or:
  
  ```bash
  sudo fdisk -l /dev/sda
  ```
  
  ---
  
- ## `gdisk`

  `gdisk` is a GPT-focused partitioning utility.
  
  Basic syntax:
  
  ```bash
  sudo gdisk /dev/sda
  ```
  
  Common commands:
  
  | Command | Action                |
  | ------- | --------------------- |
  | `p`     | Print partition table |
  | `n`     | Create partition      |
  | `d`     | Delete partition      |
  | `t`     | Change partition type |
  | `w`     | Write changes         |
  | `q`     | Quit without saving   |
  
### Important: `fdisk` and `gdisk` Do Not Automatically Represent Different "Disk Types"

Modern `fdisk` can work with GPT.

`gdisk` is specifically designed around GPT.

Therefore:

```text
fdisk ≠ MBR-only
gdisk ≠ required for every UEFI disk
```

---

##  MBR → GPT Conversion

A dangerous misconception is:

> "If I use fdisk to create an MBR partition and then use gdisk, gdisk will automatically destroy the MBR partition."

This is not generally true.

`gdisk` can detect an existing MBR partition table and offer to convert it to GPT. A conversion can preserve existing partitions if performed correctly.

However:

> **Changing a partition table is a potentially destructive operation.**

Before converting a production disk:

* Back up important data.
* Verify the existing partition layout.
* Understand the conversion procedure.
* Do not blindly write changes.

The important concept is:

> Changing the partition-table format ≠ automatically deleting all filesystem data

But an incorrect partition-table modification **can make existing data inaccessible**, so partition-table conversion should always be treated as a high-risk operation.

# Partitioning, Formatting and Mounting

These are three different operations.

- ### Partitioning

  Divides a disk into partitions.
  
  ```text
  /dev/sda
     ↓
  /dev/sda1
  /dev/sda2
  ```

- ### Formatting

  Creates a filesystem inside a partition or other block device.
  
  ```text
  /dev/sda1 → ext4 filesystem
  ```
  
- ### Mounting

  Makes the filesystem accessible through the Linux directory tree.
  
  ```text
  /dev/sda1
     ↓
  ext4
     ↓
  /data
  ```
  
Therefore:

```text
Partitioning = divide storage
Formatting   = create filesystem
Mounting     = attach filesystem to directory tree
```

# Filesystems

A **filesystem** is the data structure and software mechanism used to organize, store, locate, and retrieve files on storage.

A filesystem manages information such as:

* Files
* Directories
* File metadata
* Permissions
* Ownership
* File locations
* Free space

A partition without a filesystem cannot normally be used as a regular file-storage location.

Common Linux filesystems include:

* ext2
* ext3
* ext4
* XFS
* Btrfs

Other filesystems commonly encountered in Linux include:

* FAT32
* exFAT
* NTFS

---

##  Common Linux Filesystems

| Filesystem | Main Characteristics                                                                        |
| ---------- | ------------------------------------------------------------------------------------------- |
| **ext2**   | Older Linux filesystem; no journaling                                                       |
| **ext3**   | ext2 with journaling                                                                        |
| **ext4**   | Modern general-purpose Linux filesystem; journaling and extents                             |
| **XFS**    | High-performance journaling filesystem; excellent for large files and large filesystems     |
| **Btrfs**  | Copy-on-write filesystem with snapshots, checksums, compression and other advanced features |
| **FAT32**  | Highly compatible; maximum individual file size of 4 GiB                                    |
| **exFAT**  | Designed for flash/external storage; removes FAT32's 4 GiB file-size limitation             |
| **swap**   | Used as virtual memory; not a normal filesystem                                             |

- ### ext2

  ```text
  ext2
  ```
  
  * No journaling
  * Older Linux filesystem
  * Rarely used for modern general-purpose installations

  ---

- ### ext3

  ```text
  ext3 = ext2 + journaling
  ```
  
  It added journaling to the ext filesystem family.

  ---

- ### ext4

  `ext4` is a widely used general-purpose Linux filesystem.
  
  Important features include:
  
  * Journaling
  * Extents
  * Delayed allocation
  * Large filesystem/file support
  * Backward compatibility with ext3 in many situations

  ---

- ### XFS

  XFS is a high-performance journaling filesystem commonly used on servers.
  
  Features include:
  
  * Excellent support for large files and filesystems
  * Efficient parallel I/O
  * Online filesystem growth
  
  Important limitation:
  
  > XFS cannot shrink an existing filesystem.
  
  A filesystem that needs to be reduced generally requires a different migration strategy.

  ---

- ### Btrfs

  Btrfs is a **copy-on-write (CoW)** filesystem.
  
  Features include:
  
  * Snapshots
  * Subvolumes
  * Compression
  * Checksumming
  * Built-in RAID functionality
  
  Btrfs checksums data and metadata, which allows corruption to be detected. Actual automatic repair/self-healing generally requires a redundant copy of the data, such as an appropriate RAID configuration.
  
  ---

- ### FAT32

  FAT32 is widely supported by operating systems and devices.
  
  Important limitation:
  
  ```text
  Maximum individual file size ≈ 4 GiB
  ```
  
  It does not provide the Linux filesystem features normally expected from ext4/XFS, such as native Unix permissions.

  ---

- ### exFAT

  exFAT is commonly used for:
  
  * USB flash drives
  * SD cards
  * External disks
  * Cross-platform storage
  
  It supports files larger than 4 GiB and is widely supported across modern operating systems.

  ---

- ### swap

  Swap is storage used by Linux as an extension of virtual memory.
  
  It can be implemented as:
  
  ```text
  Swap partition
  ```
  
  or:
  
  ```text
  Swap file
  ```
  
  Swap is not a normal filesystem used to store files and directories.

---

## Journaling

A **journaling filesystem** keeps a journal of filesystem metadata operations so that the filesystem can recover more efficiently after an unexpected shutdown.

Without journaling, a crash can leave filesystem metadata in an inconsistent state and require a more extensive filesystem check.

With journaling, the filesystem can use the journal during recovery to restore filesystem consistency.

Examples of Linux filesystems with journaling include:

```text
ext3
ext4
XFS
JFS
```

Some other filesystems use different mechanisms instead of traditional journaling.

### Important

Journaling primarily protects **filesystem consistency and metadata**.

It does **not** mean:

> "Every file is automatically protected from corruption or data loss."

For example, journaling does not replace:

* Backups
* RAID
* Replication
* Snapshots

> # LVM — Logical Volume Manager
> 
> **LVM (Logical Volume Manager)** provides an abstraction layer between physical storage and filesystems.
> 
> Instead of creating filesystems directly on fixed partitions, storage can be pooled and allocated dynamically.
> 
> Basic structure:
> 
> ```text
> Physical Storage
>       ↓
> Physical Volume (PV)
>       ↓
> Volume Group (VG)
>       ↓
> Logical Volume (LV)
>       ↓
> Filesystem
>       ↓
> Mount Point
> ```
> 
> ---
> 
> ## LVM Components
> 
> - ### PV — Physical Volume
> 
>   A **Physical Volume** is storage prepared for use by LVM.
>   
>   Example:
>   
>   ```bash
>   sudo pvcreate /dev/sdb
>   ```
>   
>   A partition can also be used as a PV:
>   
>   ```bash
>   sudo pvcreate /dev/sdb1
>   ```
>   ---
> 
> - ### VG — Volume Group
> 
>   A **Volume Group** is a storage pool made from one or more physical volumes.
>   
>   Example:
>   
>   ```bash
>   sudo vgcreate my_vg /dev/sdb
>   ```
>   
>   Multiple PVs can belong to the same VG:
>   
>   ```text
>   /dev/sdb ──┐
>              ├── my_vg
>   /dev/sdc ──┘
>   ```
>   ---
> 
> - ### LV — Logical Volume
> 
>   A **Logical Volume** is allocated from a Volume Group.
>   
>   Example:
>   
>   ```bash
>   sudo lvcreate -L 10G -n home_lv my_vg
>   ```
>   
>   The resulting device is commonly accessible as:
>   
>   ```text
>   /dev/my_vg/home_lv
>   ```
>   
>   The LV can then be formatted and mounted like other block devices.
> 
> ---
> 
> ## LVM Example
> 
> Suppose we have:
> 
> ```text
> /dev/sdb = 1 TB
> /dev/sdc = 1 TB
> /dev/sdd = 1 TB
> ```
> 
> We can create:
> 
> ```text
> /dev/sdb ──┐
> /dev/sdc ──┼── VG: my_vg = 3 TB
> /dev/sdd ──┘
> ```
> 
> Then create:
> 
> ```text
> LV1 = 1.5 TB
> LV2 = 1.5 TB
> ```
> 
> Conceptually:
> 
> ```text
>              Volume Group
>                 3 TB
>                   │
>           ┌───────┴───────┐
>           ↓               ↓
>        LV1 1.5 TB      LV2 1.5 TB
>           │               │
>         ext4             XFS
>           │               │
>         /data            /backup
> ```
> 
> Each LV behaves as a block device and can be formatted with a filesystem.
> 
> ---
> 
> ## Creating LVM
> 
> Suppose `/dev/sdb` is an unused disk.
> 
> ### Step 1 — Create a Physical Volume
> 
> ```bash
> sudo pvcreate /dev/sdb
> ```
> 
> ### Step 2 — Create a Volume Group
> 
> ```bash
> sudo vgcreate my_vg /dev/sdb
> ```
> 
> ### Step 3 — Create a Logical Volume
> 
> ```bash
> sudo lvcreate -L 10G -n home_lv my_vg
> ```
> 
> Result:
> 
> ```text
> /dev/my_vg/home_lv
> ```
> 
> ### Step 4 — Create a Filesystem
> 
> ```bash
> sudo mkfs.ext4 /dev/my_vg/home_lv
> ```
> 
> ### Step 5 — Mount It
> 
> ```bash
> sudo mkdir /home2
> sudo mount /dev/my_vg/home_lv /home2
> ```
> 
> The resulting storage stack is:
> 
> ```text
> /dev/sdb
>    ↓
> PV
>    ↓
> my_vg
>    ↓
> home_lv
>    ↓
> ext4
>    ↓
> /home2
> ```
>

# `mkfs` — Create a Filesystem

`mkfs` is used to create a filesystem on a block device.

Basic syntax:

```bash
sudo mkfs -t <filesystem> <device>
```

Examples:

```bash
sudo mkfs -t ext4 /dev/sda1
sudo mkfs -t xfs /dev/sdb1
sudo mkfs -t btrfs /dev/sdc1
```

Filesystem-specific commands are preferred when available:

```bash
sudo mkfs.ext4 /dev/sda1
sudo mkfs.xfs /dev/sdb1
sudo mkfs.btrfs /dev/sdc1
```

### Warning

Formatting destroys the existing filesystem/data on the target in normal use.

Always verify the device before running `mkfs`.

```bash
lsblk
```

The generic `mkfs` command is a frontend for filesystem-specific builders such as `mkfs.ext4`.

# Creating Swap

Swap is created differently from a normal filesystem.

For a swap partition:

```bash
sudo mkswap /dev/sda2
```

Enable it:

```bash
sudo swapon /dev/sda2
```

Check active swap:

```bash
swapon --show
```

## UUID

When a filesystem is created, it normally receives a **UUID (Universally Unique Identifier)**.

Example:

```text
UUID="3f2b4c5d-1a2b-4c3d-9e8f-123456789abc"
```

You can view filesystem UUIDs with:

```bash
sudo blkid
```

or:

```bash
sudo blkid /dev/sda1
```

UUIDs are useful because device names such as:

```text
/dev/sda
/dev/sdb
```

can change depending on hardware detection order.

A UUID can remain associated with the filesystem even if the Linux device name changes.

This is particularly useful in:

```text
/etc/fstab
```

`blkid` can identify filesystem types, UUIDs, labels, and other block-device metadata.

# Mounting

A filesystem must be mounted into the Linux directory tree before it can normally be accessed through a directory.

Example:

```bash
sudo mount /dev/sda1 /mnt
```

Now:

```text
/dev/sda1
    ↓
  ext4
    ↓
  /mnt
```

Files stored under `/mnt` are stored on the filesystem mounted there.

### Temporary Mount

A filesystem mounted manually with `mount` is normally not automatically mounted after reboot.

Example:

```bash
sudo mount /dev/sdb1 /data
```

After reboot, the mount normally needs to be performed again unless it is configured for automatic mounting.

### Permanent Mount

Permanent or automatic mounts are commonly configured in:

```text
/etc/fstab
```

A typical entry:

```text
UUID=<filesystem-uuid>  /data  ext4  defaults  0  2
```

Then:

```bash
sudo mount -a
```

can be used to test the entries in `/etc/fstab`.

## Detecting New Disks and Partition Changes

Modern Linux systems normally detect newly attached storage devices without requiring a reboot.

For example:

```bash
lsblk
```

can show a newly attached disk such as:

```text
sdb
```

After modifying a partition table, the kernel may need to reread the partition table.

A common command is:

```bash
sudo partprobe /dev/sda
```

Then verify:

```bash
lsblk
```

In many situations the kernel detects the new partition information automatically.

If the kernel cannot safely reread the partition table because the disk or partitions are actively in use, a reboot may be required.

---

# `partprobe`

`partprobe` asks the kernel to reread the partition table.

Example:

```bash
sudo partprobe /dev/sda
```

Then:

```bash
lsblk
```

Use it after partition-table changes when the kernel has not yet recognized the new layout.

**Important:** `partprobe` does not create partitions. It only helps the kernel recognize an already-modified partition table.

## `mke2fs`

`mke2fs` is the underlying filesystem creation utility for:

```text
ext2
ext3
ext4
```

Basic usage:

```bash
sudo mke2fs /dev/sdb1
```

Specify filesystem type:

```bash
sudo mke2fs -t ext4 /dev/sdb1
```

The commands:

```bash
mkfs.ext2
mkfs.ext3
mkfs.ext4
```

use `mke2fs` to create the corresponding ext filesystem.

### Useful Options

| Option | Meaning                    |
| ------ | -------------------------- |
| `-t`   | Filesystem type            |
| `-L`   | Set filesystem label       |
| `-b`   | Set filesystem block size  |
| `-m`   | Reserved blocks percentage |
| `-j`   | Create a journal           |

Example:

```bash
sudo mke2fs -t ext4 -L DATA /dev/sdb1
```

### Relationship

```text
mkfs.ext4
    ↓
mke2fs -t ext4
    ↓
Creates ext4 filesystem
```

`mke2fs` is the filesystem-building engine for the ext2/ext3/ext4 family.

# Complete Linux Storage Workflow

A typical storage configuration can be represented as:

```text
Physical Disk
     ↓
Partition Table
     ↓
Partition
     ↓
Filesystem
     ↓
Mount Point
```

Example:

```text
/dev/sdb
   ↓
GPT
   ↓
/dev/sdb1
   ↓
ext4
   ↓
/data
```

Commands:

```bash
lsblk
sudo fdisk /dev/sdb
sudo mkfs.ext4 /dev/sdb1
sudo mkdir /data
sudo mount /dev/sdb1 /data
```

For permanent mounting:

```text
/dev/sdb1
    ↓
UUID
    ↓
/etc/fstab
    ↓
/data
```


And:

```text
MBR → older partition-table scheme
GPT → modern partition-table scheme

HDD → magnetic mechanical storage

SAS  → enterprise storage interface
```
